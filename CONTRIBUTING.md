# Contributing

If the video and this repository disagree, trust Alan. The mistake will be mine, and I
would like to know about it.

## Reporting something

[Open an issue](https://github.com/dbiersach/w2aew-circuits/issues/new/choose). Say which
video, and what looks wrong. That is enough. You do not need to be sure, and you do not
need to know the fix.

Corrections, better ways to model a circuit, and explanations that simply do not make
sense are all equally welcome.

## Sending a change

### Before your first commit, enable the log filter

LTspice writes the full path of your own machine into every `.log` it produces. This
repository strips those paths as a file is staged, but **Git only does that once you
switch the filter on, and it is per clone**:

```bash
git config filter.ltspicelog.clean "sh tools/strip-ltspice-log-paths.sh"
```

Run it once, from the root of your clone, before you commit anything. Without it your
username and folder layout go into the history permanently.

To check it is working, run a simulation and then look at what Git would actually commit:

```bash
git diff -- '*.log'
```

You should see changed timestamps and nothing resembling `C:\Users\...`. A pull request
that carries a path will fail its checks, so this is worth doing first rather than
discovering it later.

### The rest

1. Fork the repository, then clone your fork.
2. Make a branch: `git switch -c fix-video-412-gain`
3. Change what you came to change.
4. Open the schematic in LTspice and press **Run**, so the `.log` and the plot agree with
   the circuit. Press **Ctrl+Space** if the waveform window does not pick up the saved
   view.
5. Commit and push, then open a pull request against `main`.

## What the files are

| File | What it is |
| --- | --- |
| `.asc` | The schematic, and the source of everything else. Edit this. |
| `.plt` | The saved plot view: which traces, which colours, which axis limits. |
| `.log` | The `.meas` results the chapter notes quote. |
| `.net` | Regenerated by LTspice on every run, and not tracked. Never edit it. |
| `.raw`, `.fft` | Waveform data, not tracked. Press Run to regenerate. |
| `CIRCUIT_NOTES.md` | The chapter, one per video folder. |

Shared symbols and models live under `LTspice/` and are reached by relative path, so
moving folders about will break them.

## Two house rules

**Plot images must be genuine LTspice captures.** Cropping is fine. Redrawing a plot in
another tool, or editing pixels in one, is not, however much better it looks. The premise
of the collection is that every picture is something you can reproduce by pressing Run.

**No em dashes or en dashes** in prose. Commas and colons instead.

## What I am likely to accept

**Corrections, always.** A wrong value, a measurement that does not match the video, a
circuit that is not set up the way Alan sets his up, a sentence that says something
untrue. Send those and I will be grateful, whether as an issue or as a pull request.

**Clarity fixes, usually.** If an explanation left you stuck, saying so is useful even
when you do not have better wording to offer.

**Rewrites, probably not.** The chapters are written in one voice on purpose, and that
consistency is part of what makes them readable end to end. A pull request that reworks a
chapter's structure or style, however much better it might be on its own, is one I am
likely to decline. I would far rather say that here than after you have spent an evening
on it.

If you are planning something large, open an issue first and ask. That costs you one
message and can save you a wasted evening.

## If you are not comfortable with any of this

Open an issue describing the fix instead. That is genuinely just as useful, and I would
rather have the correction than the pull request.
