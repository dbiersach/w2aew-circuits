# LTspice dependencies

Every LTspice asset the video schematics need lives under this folder: `Models/` holds the SPICE definitions and `Symbols/` the custom symbols. Each reference to one is written as a relative path, so the collection simulates from any checkout location without a machine-specific search path. `tools/check-asset-paths.sh` checks that rule over the whole repository.

The three kinds of reference resolve differently, which matters before a file is moved:

- A `.include` or `.lib` directive resolves relative to the schematic that carries it, so a circuit two folders below the repository root writes `..\..\LTspice\Models\<vendor>\<file>`.
- A `SYMBOL` line takes the same upward relative path, as in `SYMBOL ..\..\LTspice\Symbols\sa612`. A bare name is reserved for the parts LTspice supplies itself, such as `res`, `cap`, or `Digital\dflop`.
- A `SYMATTR ModelFile` line inside an `.asy` resolves relative to the **schematic**, not to the symbol. A shared symbol therefore carries the same `..\..\LTspice\Models\...` path its schematics would write, which also means every schematic that places it has to sit at the same depth. The checker re-resolves each symbol's `ModelFile` from every schematic that places it, so a drawing filed at the wrong depth is reported rather than discovered as a missing-file error in LTspice.

LTspice doubles the separators in a relative path when it saves a drawing, so both `..\LTspice\...` and `..\\LTspice\\...` appear in these files. Both resolve, and the checker accepts either.

LTspice also supplies models for standard components from its own installation, and a schematic reaches those by a bare symbol name. The video 172 schematics place LTspice's own `lm358` symbol and the `lm358.mod` model behind it, which is why no LM358 file appears above. Parts that arrive with the simulator fall outside the rule at the top of this page, since they are not dependencies this repository carries. A vendor model can itself contain `.model` statements; the part match and source determine whether it is a physical device model or an illustrative approximation.
